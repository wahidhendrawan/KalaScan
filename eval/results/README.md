# Evaluation results

One JSON file per ruleset version (`2026.11.2.json`; the version is the first line of `kalascan rules`), written by `python3 eval/run_eval.py … --summary FILE` after a run over the whole corpus and never edited by hand. A file holds the date, the ruleset version, `score_model` when a `--score-model` flag was passed (absent means the default model), and under `groups` one entry per split (`dev`, `holdout`) and per sample set inside it (`holdout/recent-2026-11`). Each entry gives, for `malicious` and for `clean`, `total` (samples scanned), `errors` (samples that could not be scanned, which are outside `total`), and at thresholds 30, 50 and 70 the number `flagged` (risk at or above the threshold: caught for malicious, a false positive for clean) with the bounds `lo` and `hi` of its 95% Wilson interval as fractions. There are no sample names, so holdout results can be published without anyone reading a holdout sample. A file with a `source` field was not written by a run: `2026.11.1.json` was transcribed from `eval/README.md` and `docs/scoring.md`, and its `source` says what is left out. [docs/methodology.md](../../docs/methodology.md) has the method and the commands.

`2026.11.1.json` is the exception: it was transcribed from the published tables (its `source` field says so). `2026.11.2.json` is the first file written by a run.
